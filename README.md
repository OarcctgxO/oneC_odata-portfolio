# Автоматизация складских операций в 1С:WMS

Набор Python-утилит для работы с 1С:WMS через OData API: получение остатков, точный подбор партий и контейнеров под заказ, создание заданий на отбор и инвентаризацию, настройка порядка обхода ячеек и привязка контейнеров к заказам.

Проект создавался для повседневных задач на складе. Им пользовались автор и ещё два сотрудника. В репозитории сохранены исходные сценарии и структура кода; адреса баз, учётные данные и конкретные значения GUID в конфигурации заменены шаблонами, XML-метаданные и экспериментальные данные исключены.

## Какие задачи решает

| Сценарий | Что делает | Точка входа |
| --- | --- | --- |
| Получение остатков | Собирает остатки и связанные сведения о номенклатуре, партиях, контейнерах, ячейках, зонах и поклажедателях; передаёт результат в Excel | [`main_get_stocks.py`](main_get_stocks.py) |
| Точный отбор | Рассчитывает потребности заказа, подбирает партии без отрезок и формирует задания на перемещение целых контейнеров и товаров | [`main_create_pick.py`](main_create_pick.py) |
| Инвентаризация | Создаёт задания пересчёта по списку ячеек с учётом разрешённых зон и существующих заданий | [`main_create_inventarization.py`](main_create_inventarization.py) |
| Порядок обхода | Обновляет приоритеты обхода ячеек по последовательности проездов и стеллажей из `driveways_stacks.txt` | [`main_picking_route.py`](main_picking_route.py) |
| Привязка контейнеров | Привязывает контейнеры из указанной ячейки к заказу или снимает привязку | [`main_unbind_boxes.py`](main_unbind_boxes.py) |

В [`main_priem_num.py`](main_priem_num.py) также сохранены вспомогательные функции перенумерации ожидаемых приёмок и получения вида носителя номенклатуры. Текущая точка входа этого скрипта обрабатывает локальный список `er.txt`.

## Пример использования — точный отбор

Сценарий `create_pick` помогает спланировать отбор без отрезок: программа получает потребности заказа, находит доступные остатки и подбирает количества партий, сумма которых точно покрывает потребность. При выборе учитываются поклажедатель, разрешённые зоны, статусы ячеек, контейнеров и партий, а также существующие привязки контейнеров.

Для подбора используется динамическое программирование — поиск подмножества с заданной суммой. После расчёта программа формирует задания на перемещение целых контейнеров и отдельных партий. Позиции, которые невозможно собрать точно, остаются для стандартного планирования в WMS.

**[Инструкция по работе с программой «Точный отбор» — DOCX](<Инструкция по работе с программой.docx>)** содержит последовательность действий оператора, скриншоты интерфейса 1С и особенности работы. Это образец пользовательской документации к одному из сценариев проекта.

Созданные задания имеют статус «Новая»; оператор переводит их к выполнению в 1С. Ввод `0` вместо номера заказа запускает отмену найденных новых заданий отбора товаров и контейнеров с комментарием, начинающимся со «Спланировано через OData.». Эта отмена действует в выбранной базе без ограничения по заказу.

## Как устроен проект

- [`http_and_paths/`](http_and_paths/) — HTTP-запросы, авторизация, переиспользование сессии и соединений, ограничение параллелизма и работа с локальными файлами.
- [`get_stocks/`](get_stocks/) — получение и объединение складских остатков со справочными данными.
- [`create_pick/`](create_pick/) — расчёт потребностей, точный подбор и формирование заданий.
- [`patcher/`](patcher/) — чтение и изменение контейнеров и ячеек через OData.
- [`excel_paster/`](excel_paster/) — передача остатков в открытую книгу Excel через `xlwings`.
- [`config/config.py`](config/config.py) — параметры подключения, имена объектов OData и ограничения по зонам.
- [`utils/`](utils/) — форматирование дат и поиск заказа по номеру.

Сетевые операции выполняются асинхронно с помощью `asyncio` и `aiohttp`. Повторные обращения к справочным данным сокращаются кэшированием `async-lru`. Вычисление точного подбора вынесено в `ProcessPoolExecutor`. При ответе HTTP 503 предусмотрено уменьшение числа одновременно выполняемых запросов через динамический семафор.

## Установка и настройка

Код использует синтаксис Python 3.12 и новее. Для запуска нужны доступ к опубликованному OData API вашей 1С:WMS и права на соответствующие операции.

```bash
python -m pip install -r requirements.txt
```

Перед запуском:

1. В [`config/config.py`](config/config.py) укажите адреса и пути к своим базам, выберите `ACTIVE_ENV`, заполните GUID конечной зоны и ячейки, проверьте ограничения по зонам.
2. Создайте локальный `auth.txt` в корне проекта и запишите логин и пароль через пробел. Файл исключён из Git.
3. Для выгрузки остатков откройте нужную книгу Excel. Интеграция ожидает книгу `Остатки*.xlsm`, лист `Остатки` и макрос `Module1.ОчиститьОстатки`; сама книга в репозиторий не входит.

Например, после настройки можно запустить:

```bash
python main_create_pick.py
```

Имена объектов и поля OData соответствуют конфигурации 1С:WMS, с которой разрабатывался проект. При использовании с другой конфигурацией их потребуется проверить и при необходимости адаптировать. Скрипты создания и изменения объектов выполняют реальные операции в выбранной базе.

Основные зависимости: `aiohttp`, `async-lru`, `xlwings`. Полный список закреплённых версий находится в [`requirements.txt`](requirements.txt). Для сборки выгрузки остатков в EXE предусмотрен [`compile_get_stocks.bat`](compile_get_stocks.bat); PyInstaller устанавливается отдельно.
